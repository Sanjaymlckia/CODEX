# CodexHub Roadmap

CodexHub is evolving from governance-heavy to operations-light. Operational trust is now more important than feature velocity.

## PASS 0 - Unified Lifecycle + Pipeline Architecture

- Define lifecycle states as the institutional truth layer.
- Define operational pipeline stages as the workflow execution layer.
- Keep lifecycle separate from pipeline: Lifecycle != Pipeline.
- Keep operational actions separate from stages: Action != Stage.
- Avoid stage explosion; do not turn every reminder, invoice, or message into a stage.

## PASS 1 - Operational Hardening

- Intake observability.
- Email reliability and send-result visibility.
- WhatsApp fallback workflow.
- Duplicate protection.
- Runtime telemetry.
- Queue visibility.
- Trigger resilience.

## PASS 2 - Governance Simplification

- Governance compression.
- Rule lifecycle handling.
- Resume confidence.
- Drift visibility.
- Operator cognitive load reduction.

## PASS 3 - Books Integration

- Start only after operational trust stabilizes.
- Keep finance integration separate from intake/runtime stabilization.
- Preserve auditability before automation depth.

## PASS 4 - LMS Convergence + Institutional Integration

- Align learning delivery, institutional reporting, lifecycle truth, and operational records.
- Treat this as a later convergence pass after PASS 1 and PASS 2 are stable.

## Immediate Priority

Begin FODE PASS 1 operational hardening after this office bootstrap validation:

1. Operational dashboard.
2. Email observability.
3. WhatsApp fallback workflow.
4. Duplicate protection.
5. Trigger/runtime telemetry.
