# CodexHub Operational Roadmap

CodexHub should support trusted operations with the least necessary governance overhead. The direction is governance-heavy to operations-light.

## Architecture Principle

- Lifecycle is the institutional truth layer.
- Pipeline is the operational workflow layer.
- Operational actions are not stages.
- Operational trust is more important than feature velocity.

## Roadmap Passes

| Pass | Theme | Outcome |
| --- | --- | --- |
| PASS 0 | Unified lifecycle + pipeline architecture | Shared vocabulary and non-overlapping state model. |
| PASS 1 | Operational hardening | Reliable intake, queue, messaging, duplicate, trigger, and runtime visibility. |
| PASS 2 | Governance simplification | Smaller rule surface, clearer drift handling, stronger resume confidence. |
| PASS 3 | Books integration | Finance integration after operational trust stabilizes. |
| PASS 4 | LMS convergence + institutional integration | Later institutional convergence across learning, reporting, and operations. |

## PASS 1 Scope

- Intake observability.
- Email reliability.
- WhatsApp fallback workflow.
- Duplicate protection.
- Runtime telemetry.
- Queue visibility.
- Trigger resilience.

## PASS 2 Scope

- Governance compression.
- Rule lifecycle handling.
- Resume confidence.
- Drift visibility.
- Operator cognitive load reduction.
